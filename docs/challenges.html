Project Challenges

Data Collection and Parsing Challenges

The initial phase of this project faced significant obstacles in acquiring professional Counter-Strike 2 match data. The primary data source, HLTV.org, employs Cloudflare protection that actively blocks automated web scraping attempts. After implementing various scraping strategies including rotating user agents, request delays, and session management, the Cloudflare bot detection consistently identified and blocked the scraping scripts, returning 403 Forbidden responses and JavaScript challenges that could not be bypassed programmatically. This necessitated a pivot to manually downloading demo files, which severely limited the scale of data collection. Furthermore, Counter-Strike 2 introduced substantial changes to the demo file format compared to its predecessor CS:GO, rendering many existing parsing libraries incompatible. The demoparser2 library, while functional for CS2, exhibited inconsistent behavior across demo files from different game versions and tournament organizers. Approximately 35% of collected demo files (7 of 20) were either corrupted, incomplete, or contained parsing errors that caused the extraction pipeline to fail. Debugging these failures required extensive inspection of demo file structures, tick-by-tick event analysis, and implementation of robust error handling to skip malformed rounds while preserving valid data. The integer overflow bug discovered during feature extraction—where equipment advantage calculations using unsigned 64-bit integers caused negative values to wrap around to extremely large positive numbers—exemplifies the subtle technical issues that consumed significant development time.

Feature Engineering and Statistical Challenges

Beyond data acquisition, the computational and statistical aspects of this project presented formidable challenges. Extracting time-series features from demo files proved prohibitively time-intensive, with each 30-round match requiring approximately 15-20 minutes of processing time to parse tick-level data at 10-second intervals throughout every round. This constraint limited the practical dataset size to 2,507 samples from 13 matches—a relatively small dataset for training robust machine learning models, particularly ensemble methods that benefit from large sample sizes. The limited data increased the risk of overfitting and reduced the statistical power of model comparisons. Additionally, exploratory analysis revealed substantial multicollinearity among the engineered features. Equipment values for each team correlated strongly with their respective armor totals (r > 0.85), player count advantages correlated with health totals, and the various multi-kill metrics (2K, 3K, 4K, 5K) exhibited near-perfect correlation with total kills. This multicollinearity violates assumptions of certain statistical methods and can inflate variance in coefficient estimates, making feature importance rankings less reliable. While tree-based ensemble methods like Gradient Boosting are relatively robust to multicollinearity for prediction purposes, the interpretability of individual feature contributions becomes questionable when features share redundant information. Attempts to address this through feature selection and PCA-based dimensionality reduction helped for clustering analysis but introduced complexity in mapping predictions back to actionable game insights.

What Worked Well

Despite these challenges, several aspects of the project succeeded beyond initial expectations. The state-based time-series feature engineering approach produced a dramatic 27.95 percentage point improvement in prediction accuracy, validating the hypothesis that measuring game state before outcomes occur provides genuine predictive signal. The Gradient Boosting model achieved 86.65% accuracy with a ROC AUC of 0.942, demonstrating that professional CS2 round outcomes are substantially predictable given appropriate features. The clustering analysis successfully identified two distinct player archetypes (Entry Fraggers and Support players) that align with established competitive gaming roles, providing external validation of the methodology. The discovery that equipment advantage dominates round predictions—accounting for 28.2% of feature importance—provides actionable insight for competitive players and coaches.

What Did Not Work Well

The Naive Bayes classifiers performed poorly (52-54% accuracy), demonstrating that their independence assumption is fundamentally violated by the correlated nature of game state features. Simple decision trees without ensemble methods achieved only marginally better than random guessing, confirming that the prediction task requires capturing complex feature interactions that single trees cannot model. The positional analysis originally envisioned for this project—identifying optimal map positions and movement patterns—was not completed due to the complexity of extracting, normalizing, and analyzing 3D coordinate data across different maps with varying geometries. Several research questions posed in the introduction, particularly those regarding timeout effects and detailed positional strategies, remain unanswered.

Future Research Directions

Future work should prioritize expanding the dataset through alternative data collection methods, potentially including official API access or partnerships with tournament organizers. Incorporating player position coordinates would enable spatial analysis of optimal holding spots, rotation timings, and site execution strategies. Modeling round-to-round economic dependencies could capture the momentum effects that experienced players recognize but that current per-round models ignore. Deep learning approaches, particularly LSTM networks, could better model the sequential nature of round progression and capture temporal patterns that tree-based methods miss. Finally, real-time prediction systems could provide live strategic insights during matches, though this would require optimizing feature extraction for sub-second latency.
